# 스케줄러 — GCP 이관 의사결정

## 문제 / 질문

GCP로 데이터플랫폼을 이관할 때 Airflow 스케줄러를 어떻게 띄울지.
단일 결정이 아니라 **트리 구조의 결정 묶음**이다.

### 메인 결정

**Self-managed (GKE) 위에 Airflow 직접 운영 vs Cloud Composer 사용**

### 부수 결정 (메인 결정 따라 종속됨)

| 부수 결정 | 옵션 | 비고 |
|---|---|---|
| Airflow 버전 | 2.x / 3.x | Composer 2 = Airflow 2 / Composer 3 = Airflow 3 — 인프라 선택과 묶임 |
| Executor 종류 | LocalExecutor / Celery / Kubernetes / CeleryKubernetes | Composer는 CeleryKubernetes 거의 고정 |
| Worker queue 전략 | 단일 / queue별 분리 | Composer는 분리 어려움 |
| Metadata DB | Cloud SQL / AlloyDB / Self-hosted | Composer는 Cloud SQL 자동 |
| Pod 스펙 / Pool | factory 패턴, 동시성 제한 | 양쪽 다 가능 |
| 권한·인증 | IAP / OIDC, RBAC 매핑, Workload Identity | Composer 자동, Self-managed 직접 |
| dbt 실행 방식 | KubernetesPodOperator / BashOperator + dbt-core | Executor 선택과 묶임 |

## 결정 순서 (Decision tree)

```
1단계: Airflow 버전을 2.x로 유지할지, 3.x로 점프할지
        → 일반적으로 3.x 권장 (Composer 2 EOL 흐름, 보안/언어 SDK 개선)
        → 마이그레이션 비용은 plugin / 내부 API 의존 코드에 집중
        → 결정 자료: [[6_Airflow 2 vs 3 비교]]

2단계: 인프라 — Composer 3 (= Airflow 3) vs Self-managed (Airflow 3 on GKE)
        → 운영 인력 / 자유도 / queue 분리 필요성 / 비용 / 권한 관리
        → 결정 자료: [[2_Cloud Composer vs Self-managed 비교]], [[7_Composer 비용]], [[8_Composer 권한 및 인증]]

3단계: 세부 — Executor / Queue / Pod 스펙 / DB / dbt 통합
        → 인프라 선택 결과에 따라 자유도 다름
        → 결정 자료: [[3_Executor 종류 및 비교]], [[4_Queue 라우팅과 Pod 스펙 설정]], [[5_Metadata DB 운영]]
```

## 주요 트레이드오프

### Composer 선택 시 잃는 것

- Executor 자유 선택 (CeleryKubernetes 거의 고정)
- system 패키지 자유 설치 (Dockerfile 완전 제어 X)
- Worker queue별 분리 (단일 worker pool)
- airflow.cfg 완전 제어
- 비표준 storage 사용
- Multi-tenancy를 단일 클러스터로 처리 (환경별 분리 강제 → 비용)

### Self-managed 선택 시 잃는 것

- 운영 인력 0.2~0.5 FTE (업그레이드 / 패치 / 트러블슈팅 / on-call)
- 빠른 마이그레이션 (Composer 환경 생성은 분 단위 vs Self는 일/주 단위)
- IAP / Workload Identity / Secret Manager / Logging 자동 통합 → 직접 구성
- Snapshot 자동 백업 → 직접 구성
- Composer 3의 IAM ↔ Airflow Role 자동 매핑

### Airflow 2 → 3 점프 시 잃는 것 (얻는 것)

- 잃는 것: 마이그레이션 시간 (DAG 일부 수정, plugin 검토, provider 호환 확인)
- 얻는 것: Task SDK 격리(보안 ↑), DAG versioning, Asset/AssetWatcher, DAG Bundles, 장기 지원
