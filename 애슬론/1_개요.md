# 애슬론 — 플랫폼 재구현 의사결정

## 문제 / 질문

ETL은 `athlon (neptune)` → **dbt** 로, 쿼리 엔진은 `presto` → **BigQuery** 로 전환이 확정되었다.
이 결정 위에서 **athlon 플랫폼(athlon + athlon-ui)은 어떻게 재구현되어야 하는가?**

세부 질문:

1. **dbt 모델 관리 방식**: athlon이 dbt 코드를 어떻게 품을지
2. **워크플로 / 액션 모델**: 기존 `actions` / `workflows` / `actions_meta` 개념을 어떻게 재정의할지
3. **Userlake**: 쿼리 생성 로직을 어떻게 BQ로 옮길지
4. **extract**: GCP native 대체 도구가 있는지, 유지/대체 결정
5. **UI 변화**: athlon-ui에서 dbt 편집·의존성 시각화·git 연동을 어떻게 구성할지
6. **마이그레이션 전략**: 기존 ETL을 dbt로 옮기는 절차 (자동/반자동/수동)
