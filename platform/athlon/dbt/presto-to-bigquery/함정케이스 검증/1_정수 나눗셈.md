# 1. 정수 나눗셈 — `/` 의 반환 타입이 다르다

- 검증일: 2026-09-03
- 검증자: diana (Presto adhoc / BigQuery `dev-dp-project-354904`)
- 분류: ⚠ 조용히 결과가 달라지는 함정 (문법 에러 없음)

## 무엇이 다른가

| | Presto | BigQuery |
| --- | --- | --- |
| `int / int` | **정수 나눗셈** (절삭) | **항상 FLOAT64** |
| 음수 절삭 방향 | 0 방향 (`-5/2 = -2`) | (나눗셈 자체가 실수라 해당 없음) |

원본 presto 쿼리의 `a / b` 를 BQ 로 그대로 옮기면 문법 에러 없이 값이 달라진다
(예: 비율 계산을 정수 절삭에 의존하던 쿼리, 버킷 인덱스 계산 등).

## 검증 쿼리와 실측 결과

**Presto:**

```sql
SELECT
    1/2          AS a,   -- 결과: 0
    5/2          AS b,   -- 결과: 2
    -5/2         AS c,   -- 결과: -2  (0 방향 절삭)
    5.0/2        AS d,   -- 결과: 2.5 (한쪽이 실수면 실수 나눗셈)
    typeof(1/2)  AS t    -- 결과: integer
```

**BigQuery:**

```sql
SELECT
    1/2                 AS a,   -- 결과: 0.5  ← 함정 본체
    5/2                 AS b,   -- 결과: 2.5
    -5/2                AS c,   -- 결과: -2.5
    DIV(5, 2)           AS d,   -- 결과: 2    (올바른 대체)
    DIV(-5, 2)          AS e,   -- 결과: -2   (0 방향 절삭 — presto 와 동치)
    CAST(5/2 AS INT64)  AS f    -- 결과: 3 ⚠  (반올림!)
```

## 결론

1. **함정 성립**: presto `5/2 = 2` vs BQ `5/2 = 2.5`.
2. **올바른 대체는 `DIV(a, b)` 하나** — 음수 절삭 방향(0 방향)까지 presto 와 완전 동치.
3. **`CAST(x/y AS INT64)` 는 금지** — BQ 의 CAST 는 절삭이 아니라 **반올림**
   (`CAST(2.5 AS INT64) = 3`). 절삭이 필요하면 `DIV()` 또는 `TRUNC()` 후 캐스팅.
   (검증 전 변환표 비고에 CAST 를 대체 수단으로 적어놨었는데, 이 실측으로 오류로
   판명되어 표에서 제거함)
