# 스케줄러 — GCP 이관 의사결정

## 문제 / 질문

GCP로 데이터플랫폼을 이관할 때, **Airflow를 Cloud Composer 2로 띄울 것인가, GKE에 Self-managed로 직접 띄울 것인가?**

## 핵심 결론

> _(검토 완료 후 한 줄로 채울 자리)_

## 결정 근거 (요약)

| 평가 축 | Cloud Composer 2 | Self-managed (GKE) | 우리 선택 |
|---|---|---|---|
| 운영 인력 부담 | 낮음 (GCP 자동화) | 높음 | |
| 구성 자유도 (Executor / Dockerfile / 패키지) | 제한적 | 완전 | |
| Worker queue 분리 | 어려움 (단일 worker pool) | 자유 | |
| 비용 | 환경 패키지 ($300~$3000/월) | 노드 + DB (실사용량 기반) | |
| 업그레이드 / 패치 | 자동 | 수동 | |
| GCP 서비스 통합 (Workload Identity, IAP 등) | 깊음 | 직접 구성 | |
| 마이그레이션 속도 | 빠름 | 느림 | |
| Metadata DB 운영 | 자동 (Cloud SQL) | 직접 (Cloud SQL / 자체) | |

상세 비교는 [[2_Cloud Composer 2 vs Self-managed 비교]] 참조.

## 트레이드오프

- **Composer 선택 시 잃는 것**: Executor 자유, system 패키지 설치 자유, worker queue 분리, Dockerfile 완전 제어
- **Self-managed 선택 시 잃는 것**: 운영 인력 시간, 빠른 도입, GCP 통합 자동화 (Workload Identity, Cloud Logging 자동)

## 우리 컨텍스트에서 중요한 점

- _(예: 사내 어떤 패키지 / 시스템 라이브러리 필요한가? — Composer 감점 가능)_
