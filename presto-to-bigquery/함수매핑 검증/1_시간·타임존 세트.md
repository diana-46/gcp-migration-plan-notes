# 1. 시간·타임존 세트 — UTC 세션 기준 전부 동치

- 검증일: 2026-09-03
- 검증자: diana (Presto: presto-cli **UTC 세션** — ETL 실행 환경과 동일 / BigQuery: `dev-dp-project-354904`)
## 검증 쿼리

**Presto** (`presto-cli UTC ... --file`):

```sql
SELECT
    current_timezone()                                         AS tz,
    now()                                                      AS a1,
    current_date                                               AS a2,
    CAST(TIMESTAMP '2026-09-03 20:00:00 UTC' AS TIMESTAMP)     AS a3,
    TIMESTAMP '2026-09-03 20:00:00' AT TIME ZONE 'Asia/Seoul'  AS a4,
    date_diff('day', DATE '2026-09-01', DATE '2026-09-03')     AS b1,
    to_unixtime(TIMESTAMP '2025-09-03 00:00:00')               AS b2,
    from_unixtime(1756857600)                                  AS b3
;
```

**BigQuery:**

```sql
SELECT
    CURRENT_TIMESTAMP()                                         AS a1,
    CURRENT_DATE()                                              AS a2u,
    CURRENT_DATE('Asia/Seoul')                                  AS a2k,
    DATETIME(TIMESTAMP '2026-09-03 20:00:00+00', 'Asia/Seoul')  AS a4,
    DATE_DIFF(DATE '2026-09-03', DATE '2026-09-01', DAY)        AS b1,
    UNIX_SECONDS(TIMESTAMP '2025-09-03 00:00:00+00')            AS b2,
    TIMESTAMP_SECONDS(1756857600)                               AS b3
```

## 실측 결과 (주제별 페어 비교)

쿼리의 컬럼 라벨(a1, b2 등)은 실행 당시 것 — 아래는 주제별로 재배열.

### ① 세션·현재 시각

| | Presto (UTC 세션) | BigQuery | 판정 |
| --- | --- | --- | --- |
| 세션 TZ | `current_timezone()` → `UTC` | (세션 개념 없음 — 항상 UTC) | 동일 전제 확인 |
| 현재 시각 | `now()` → `2026-09-03 09:23:38 UTC` | `CURRENT_TIMESTAMP()` → `09:21:24 UTC` | ✅ 동일 instant |
| 오늘 날짜 | `current_date` → `2026-09-03` | `CURRENT_DATE()` → `2026-09-03` (KST 필요 시 `CURRENT_DATE('Asia/Seoul')`) | ✅ |

### ② 타임존 변환 (이관 핵심)

| | Presto (UTC 세션) | BigQuery | 판정 |
| --- | --- | --- | --- |
| naive → KST | `TIMESTAMP '2026-09-03 20:00:00' AT TIME ZONE 'Asia/Seoul'` → `2026-09-04 05:00 Asia/Seoul` | `DATETIME(TIMESTAMP '... 20:00:00+00', 'Asia/Seoul')` → `2026-09-04T05:00:00` | ✅ **동치** |
| tstz → naive | `CAST(TIMESTAMP '... 20:00:00 UTC' AS TIMESTAMP)` → `20:00:00` (세션=UTC 라 무손실) | (해당 없음 — TIMESTAMP 가 항상 instant) | 세션 의존 확인용 |

### ③ 날짜 연산

| | Presto | BigQuery | 판정 |
| --- | --- | --- | --- |
| 날짜 차이 | `date_diff('day', 9/1, 9/3)` → `2` | `DATE_DIFF(9/3, 9/1, DAY)` → `2` | ✅ **인자 순서 반대** 확정 |

### ④ epoch 왕복

| | Presto (UTC 세션) | BigQuery | 판정 |
| --- | --- | --- | --- |
| ts → epoch | `to_unixtime('2025-09-03 00:00')` → `1.7568576E9` (**DOUBLE**) | `UNIX_SECONDS(... +00)` → `1756857600` (INT64) | ✅ 값 동일, 타입/표기 차이 |
| epoch → ts | `from_unixtime(1756857600)` → `2025-09-03 00:00` | `TIMESTAMP_SECONDS(...)` → 동일 | ✅ |

## 결론

UTC 세션(= Neptune ETL 실행 환경 `run_presto_sql_khp.sh UTC`) 기준으로 **전부 동치**:

1. `ts AT TIME ZONE 'Asia/Seoul'` ≡ `DATETIME(ts, 'Asia/Seoul')` — 이관의 핵심 변환 검증.
2. `date_diff('day', a, b)` ≡ `DATE_DIFF(b, a, DAY)` — **인자 순서 반대** 실측 확정.
3. `to_unixtime` ≡ `UNIX_SECONDS` — 단 presto 는 **DOUBLE**(`1.75E9` 표기),
   BQ 는 INT64. 문자열로 쓰던 쿼리면 포맷 차이 주의.
4. `from_unixtime` ≡ `TIMESTAMP_SECONDS`, `now()` ≡ `CURRENT_TIMESTAMP()`,
   `current_date` ≡ `CURRENT_DATE()` (UTC).
