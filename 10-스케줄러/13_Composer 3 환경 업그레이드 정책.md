# Cloud Composer 3 환경 업그레이드 정책 (공식 문서 정리)

> Cloud Composer 3 의 환경 업그레이드 정책 정리. 출처: [Cloud Composer 3 — Upgrade environments](https://cloud.google.com/composer/docs/composer-3/upgrade-environments)

## 1. 업그레이드의 두 가지 방식 분리

| 방식                      | 트리거                | 영향                                                    |
| ----------------------- | ------------------ | ----------------------------------------------------- |
| **자동 인프라 업그레이드**        | Managed Airflow 자동 | 환경의 인프라 구성요소 — Airflow 작동 방식이나 DAG 실행 방식을 **변경하지 않음** |
| **수동 Airflow 버전 업그레이드** | 사용자 수동 트리거         | 새로운 Airflow 버전 또는 빌드로 업그레이드                           |

## 2. 인프라 업그레이드와 유지보수 기간 (매우 중요)

- Managed Airflow (3세대) 에서는 **자동 인프라 업그레이드를 사용 중지할 수 없음**
- 대신 해당 환경에 대해 **커스텀 유지보수 기간** 을 지정하여 자동 업그레이드가 실행될 수 있는 기간을 제어 가능
  - (이전 화면에서 '기본값'으로 설정되어 있던 부분을 **DAG 가 덜 도는 시간** 으로 수정하는 것을 권장)
- 자동 인프라 업그레이드로 인해 Airflow 구성요소가 **재시작될 수 있음**
- 이러한 재시작 중에는 **24시간의 유예 기간** 을 두고 Airflow 작업자가 정상적으로 종료됨

### 2.1 유지보수 기간 설정의 목적

Cloud Composer 3 는 시스템 안정성을 위해 Google 이 진행하는 자동 인프라 업그레이드를 **완전히 끌 수 없음**. 대신 이 설정을 통해:

> "우리 서비스가 가장 여유로운 시간대 (예: 새벽이나 주말) 에만 업그레이드를 진행해라"

하고 **안전한 타임슬롯을 지정**해 주는 역할.

### 2.2 핵심 설정 기능 2가지

문서에서는 인프라 업그레이드 타이밍을 제어하기 위해 다음 두 가지 기능을 제공한다고 명시:

#### 🕐 유지보수 기간 (Maintenance Windows)

- 자동 업그레이드가 **시작될 수 있는** 요일 / 시작 시간 / 지속 시간을 지정
- 지속 시간은 **최소 4시간 이상**
- 일반적으로 **매주 특정 시간에 반복** 되도록 구성
- 이 시간 창 (Window) **을 벗어나서는 Google 이 인프라를 건드리지 않음**

#### 🚫 유지보수 제외 기간 (Maintenance Exclusions)

- **대규모 데이터 정산일 / 대대적인 서비스 런칭 / 이벤트 기간** 등 절대로 인프라 업데이트가 일어나면 안 되는 고정된 날짜와 기간을 지정
- 업그레이드를 **명시적으로 차단** 가능

### 2.3 업그레이드 진행 시 워커 보호 정책

유지보수 기간에 인프라 업그레이드가 실행되어 내부 컴포넌트나 워커가 재시작되어야 할 때, 돌고 있는 작업들을 보호하는 메커니즘:

**24시간 유예 기간 (Grace Period)**:
- 실행 중인 Airflow 태스크가 기습적으로 끊겨 실패하지 않도록, 기존 작업을 안전하게 마무리할 수 있는 **최대 24시간의 유예 기간** 을 작업자 (Worker) 에게 부여
- 작업자는 **기존 태스크를 다 끝내거나 24시간이 지나기 전까지는 강제 종료되지 않음**

## 3. Airflow 버전 (수동) 업그레이드 시 제한사항

- ❌ Airflow 의 이전 빌드 또는 버전으로 **다운그레이드 불가**
- ⚠️ 24시간 유예 기간을 주는 인프라 업그레이드와 달리, **환경이 새로운 Airflow 버전 또는 빌드로 업그레이드되면 실행 중인 모든 태스크가 즉시 종료**됨
- ❌ Airflow 데이터베이스에 **20GB 가 넘는 데이터** 가 포함된 경우 환경을 업그레이드할 수 없음

## 4. 스냅샷 권장 사항

문서의 '시작하기 전에' 항목에서도 명시적으로 권장:

> "필요한 경우 환경을 다시 만들 수 있도록 환경의 **새 스냅샷을 만드는 것이 좋습니다**."

## 5. 결론

3세대에서는 GKE 와 같은 인프라 구성을 Google 이 완전히 자동 관리하므로 (끌 수 없도록 고정) **치명적인 장애를 피할 수 있게 되었음**.

다만 Airflow 자체의 마이너 버전업은 사용자의 선택에 맡겨져 있으므로, 업그레이드 전에는 **반드시 스냅샷을 찍어두는 것** 이 공식 문서에서도 요구하는 안전한 운영 방식.
